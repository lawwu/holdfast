03 / KEEP THE IMPORTANT BOUNDARIES

The opportunity is additive.

MLX already has a bridge.

Holdfast’s resolved mlx-swift-lm dependency includes MLXFoundationModels, though the app does not currently import it. On macOS 27, it can run your chosen weights through Apple’s session API. This makes a same-model comparison practical. Bridge docs

Structured JSON has another route.

The same dependency offers standalone MLXGuidedGeneration on macOS 14+. If parsing is the only problem, compare this smaller change: it fits Holdfast’s macOS 15 baseline. Apple’s system model and native sessions are additional benefits. Constrained generation

Holdfast still owns trust.

Keep local-only routing, source checks, validated edits, Inbox approval, snapshots, and Undo in the app. Current private-content fallback explicitly selects LocalMLX. Supporting Apple’s on-device model would require an intentional policy update; cloud profile switches must never inherit protected history. PiAgent.swift

Search and audio remain separate.

Retain SQLite/FTS, embeddings, reranking, and transcription. Apple’s Spotlight search is worth a later comparison, but replacing Holdfast’s retrieval would also need to preserve source anchors and private-folder rules. Index.swift · Spotlight retrieval

Typed output guarantees shape, not truth. Apple’s guardrails can also refuse benign transformations; include Holdfast’s sensitive-note use cases in evaluation. Refusal behavior ↗

04 / YOUR CLOUD QUESTION

Apple’s cloud model is AFM 3 Cloud.

It is Apple’s own larger model, exposed through PrivateCloudComputeLanguageModel. Private Cloud Compute is the infrastructure that runs it on Apple servers. It supports text and images, guided output, tools, and configurable reasoning. Apple’s model documentation ↗

32K context

More room for sources and tool results than Apple’s on-device models. Reasoning also uses context. Technical session

No API-key setup

The OS handles access. Eligible developers pay no cloud API fee, but users have daily limits; iCloud+ increases them. Integration guide

Private, yet remote

Apple says request data is not retained. It still leaves the Mac, so it cannot satisfy Holdfast’s existing “this Mac only” promise. Privacy description

App Store approval alone does not unlock PCC.

Production eligibility requires App Store distribution, Small Business Program enrollment, fewer than two million first-time App Store downloads under Apple’s eligibility rules, and the PCC entitlement. Testing is permitted through TestFlight or ad hoc distribution. Holdfast’s current direct-download channel is outside the published production allowance. Eligibility rules ↗

Recommendation: pursue an App Store version for its distribution value. Treat PCC as an optional capability with quotas and a fallback, not the sole reason to undertake the migration.

05 / GETTING HOLDFAST INTO THE MAC APP STORE

A separate release channel, with some engineering first.

The current installer is signed and notarized for direct distribution. A Mac App Store release uses a different signing and submission workflow and must enable Apple’s App Sandbox, which limits file, network, and hardware access to granted permissions. Apple’s requirement ↗

Repository evidence: sign_app.py · App.swift · AppUpdates.swift · Ingest.swift · make_app.sh. This is a focused source inspection, not a complete Store compliance audit or a submission result.

  1. Confirm the developer account.

    The Apple Developer Program is US$99/year, with local pricing where available. Holdfast’s Developer ID release suggests you may already be enrolled; confirm membership and App Store Connect access. Organization enrollment needs a legal entity and D‑U‑N‑S number. Enrollment

  2. Create the Store app record.

    Register the App ID and add a macOS app in App Store Connect with its name, bundle ID, and SKU. Choose the distribution identity and provisioning for the Store build; existing Developer ID signing serves the direct channel. Add an app · Signing identities

  3. Build and test the Store variant.

    Make the changes above, archive and upload using Apple’s distribution tooling, then test through TestFlight. Exercise a fresh install, vault access after relaunch, downloads, microphone/system audio, private routing, and helpers. TestFlight

  4. Prepare the listing and submit.

    Add screenshots, description, support and privacy-policy URLs, age rating, pricing, availability, and review instructions. Complete privacy and export-compliance questions accurately. Supply synthetic notes so review can exercise the app without real private data. Then select the build and submit. Submission workflow · Privacy details

If you want PCC: also enroll in the Small Business Program if eligible, request the PCC entitlement, and provision the app accordingly. Check availability and user quota in the feature. Those approvals are separate from ordinary Developer Program membership.

06 / FIRST EXPERIMENT COMPLETED

Evidence before a runtime change.

The bounded cross-link experiment completed 102 local requests: 96 scored decisions and six warm repeats. Every arm used the same synthetic pairs and existing approval behavior. Labels remain provisional for your review.

Faster responses came with more false links.

Across 32 scored decisions per arm, current MLX and constrained MLX each had zero false links and two misses. Apple had six false links and zero misses. Median response times were 13.94s, 12.63s, and 1.57s respectively. All scored replies passed the schema check; no refusals or backend errors were recorded.

The original safety probes found that malformed positive JSON and a string-valued Boolean could create Inbox proposals. The parser is now fixed, with all 23 safety checks passing. Private notes were excluded, source notes stayed unchanged until explicit Apply, and Undo restored their bytes. No runtime was switched. Read the parser fix and safety recheck.

Compare

Separate the variables.

Current MLX output; the same MLX weights with constrained JSON; Apple’s system model with typed output. Record OS, model variant, context budget, cold/warm latency, and memory.

Decide

Quality before convenience.

Use human-labeled pairs. Track false links, missing links, refusals, schema failures, and total completion time. Adopt only if the observed trade-off is worthwhile.

Protect

Test the guarantees separately.

Private notes remain excluded. Failures create no links. Proposals still await approval. On unsupported or unavailable systems, preserve the existing local path.

For a later runner comparison, reuse Holdfast’s agent fixtures and add long histories, cancellation, recovery, and private routing. Apple’s Evaluations framework can help measure model quality; deterministic privacy and edit checks still belong in ordinary tests.

What this research does not establish

The experiment is exploratory: sixteen unique pairs, provisional labels, two passes, one M1 Max, and AFM 3 Core. It does not establish performance on Core Advanced, true cold-model latency, Apple’s total model memory, battery impact, or production reliability. The app’s existing local path is unchanged; old-OS execution and forced Apple unavailability were not tested. App Store acceptance, account eligibility, and PCC entitlement were not verified. Model readiness, region, language, OS version, and device variant can change availability.
