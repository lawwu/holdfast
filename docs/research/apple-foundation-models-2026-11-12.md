# Apple Foundation Models: evidence for Holdfast

Research date: November 12, 2026 (America/Los_Angeles). Sources are Apple documentation, Apple WWDC transcripts, Apple research, and repositories linked by Apple. The original research left application files unchanged. The subsequent experiment and parser fix are recorded in the addendum below.

## Measured follow-up: keep the current runtime

**Parser follow-up:** [all 23 integration safety checks now pass](../../eval/crosslink-comparison/results/2026-11-12-parser-fix/report.md), plus 43 standalone parser cases. All 102 recorded model replies retain their decisions. MLX and its configuration remain unchanged. The experiment findings below describe the original pre-fix baseline.

The [cross-link report](../../eval/crosslink-comparison/results/2026-11-12-three-arm/report.html) records 102 local requests on an M1 Max with 64 GiB, macOS 27.2: sixteen fixed public synthetic pairs, two reversed-order passes per arm, and six warm repeats. The user authorized provisional labels and will review them; these are not yet human-validated ground truth.

Across 32 scored trials per arm, current Qwen3.8-27B-4bit MLX and the same weights with JSON constraints each produced zero false links and two missed links against the provisional labels. AFM 3 Core typed output produced six false links and zero misses. Median request times were 13.94s, 12.63s, and 1.57s respectively. All scored replies passed the strict schema check; no backend errors or refusal matches were recorded. Adding the grammar did not improve observed decision quality or schema validity on this small corpus.

Independent probes exposed two existing parser failure modes: malformed positive JSON and a string Boolean can produce proposals. Private/confidential exclusions, the approval boundary, and Undo passed. No runtime change or model adoption was made. The [label sheet](../../eval/crosslink-comparison/results/2026-11-12-three-arm/label-review.html), raw records, source/weight hashes, and measurement limits are retained with the report. First-use measurements do not establish a truly cold model, and Apple's runner memory is not its total inference memory.

## What changed since the original framework

The current framework is broader than the original on-device API. Apple's overview now includes arbitrary model providers, Private Cloud Compute (PCC), images, Dynamic Profiles, Evaluations, and command-line tooling. Treat the framework, Apple's models, and third-party model implementations as separate choices. [Apple overview](https://developer.apple.com/foundation-models-framework/)

| Deployment generation | Relevant capabilities and limits |
| --- | --- |

| 26.0–26.3 / 26.4 | Apple distinguishes model versions for 26.0–26.3, 26.4, and 27.0. [SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel) |

## On-device model choice and context

Apple currently documents two on-device variants: AFM Core (3 billion parameters, 4–8K context) and AFM Core Advanced (20 billion parameters, 8K context). On macOS 27, M3-or-later Macs receive Core Advanced; supported older Macs receive Core. Each device has one system variant and version, chosen by the OS. Inspect `variant`, availability, and `contextSize` at runtime. Context can differ even within a variant/version. [Model detection and hardware table](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models)

Core Advanced is sparse: Apple describes 1–4 billion active parameters per request, out of 20 billion total. Its architecture stores weights in flash and loads selected experts; “20B” is not a claim that all weights reside in working memory. Apple's published model comparisons are its own evaluations, not evidence of performance on Holdfast's workload. [Apple's third-generation model research](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models)

The WWDC PCC code explicitly shows 4,096 tokens on 26.0, 8,192 on newer devices running 27.0, and 32,768 for PCC. Some surrounding documentation still says “4K” without qualification. Prefer the runtime property over a global fixed-context assumption. Reasoning tokens also consume PCC context. [PCC session, especially code at 5:58](https://developer.apple.com/videos/play/wwdc2026/319/)

The context budget includes instructions, tool definitions, tool inputs/results, response schemas, prompts, and generated responses. A long transcript can exhaust it before the visible user message looks large. Trim history or start a fresh session when the context is exceeded. [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window)

Apple positions on-device models for summarization, extraction, refinement, creative text, and text/image understanding. Its prompting advice recommends concise, focused tasks and splitting complex work when necessary. **Inference for Holdfast:** bounded extraction or ranking supplied candidates is a better first experiment than assuming an entire long-running agent will transfer unchanged. This remains an evaluation question, especially across Core and Core Advanced. [Framework reference](https://developer.apple.com/documentation/foundationmodels/), [on-device prompting](https://developer.apple.com/documentation/foundationmodels/prompting-an-on-device-foundation-model)

Availability is more than an OS version: hardware, region, storage/model preparation, and model readiness matter. For OS 26, Apple Intelligence can be disabled; the current detection article says it is enabled by default and cannot be disabled on OS 27. Preserve version-specific handling instead of always telling users to turn it on. [Model availability](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models)

## Structured output and tools

`@Generable` describes Swift output types; `@Guide` adds field descriptions and constraints. `DynamicGenerationSchema` supports choices known only at runtime, such as a supplied list of valid destinations. Apple's guarantee concerns output format. **Inference:** a valid identifier or correctly shaped object can still be the wrong answer. Validate source IDs, evidence spans, allowed destinations, and proposed edits in application code. [Guided generation](https://developer.apple.com/documentation/foundationmodels/generating-swift-data-structures-with-guided-generation)

`Tool` is an executable Swift interface. The model chooses tools, arguments are generated, application code executes, and results return to the model before its final answer. Calls can repeat and execute concurrently. This is an orchestration loop, not merely JSON emitted for a separate runner. Tool exceptions become `ToolCallError`; a tool can instead return a short failure result. The current API supports allowed/required/disallowed tool modes; required mode needs an exit condition or it keeps calling tools. **Inference:** integrating a native session into another agent runner requires an explicit decision about which layer owns execution and approval. [Tool calling](https://developer.apple.com/documentation/foundationmodels/expanding-generation-with-tool-calling)

Dynamic Profiles can change instructions, tools, model, sampling, and reasoning configuration in one session. `historyTransform` changes what a request sees without mutating the global transcript. **Inference:** profile switching is not itself a privacy boundary: the application must decide which history is eligible to cross from a local model to a server. [DynamicProfile reference](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/dynamicprofile), [agentic app session](https://developer.apple.com/videos/play/wwdc2026/242/)

## Private Cloud Compute: the distribution gate matters

Apple's eligibility page requires App Store Small Business Program enrollment, fewer than two million first-time App Store downloads, and the managed PCC entitlement. It authorizes production use in apps distributed on the App Store, plus testing through TestFlight or ad hoc distribution; test installs do not count. If any app crosses the threshold or the developer leaves the program, Apple gives six months to migrate. **Conclusion for planning:** the published terms do not authorize ordinary direct-distributed production Mac apps. Do not promise PCC for that channel without a separate Apple determination. The page does not publish an alternate paid API tier or a direct-distribution exception. [PCC eligibility](https://developer.apple.com/private-cloud-compute/)

PCC has no cloud API cost to eligible developers, uses OS/iCloud integration rather than developer-managed API keys, and has daily per-user quotas; iCloud+ provides higher limits. It needs a network connection and Apple Intelligence eligibility. The API exposes quota status and reset date, with a distinct quota-limit error; exhausted daily quota is different from short-term rate limiting. Apple's documentation recommends persistent status UI and provides Xcode quota simulation. [PCC integration guide](https://developer.apple.com/documentation/foundationmodels/adding-server-side-intelligence-with-private-cloud-compute)

Apple states PCC data is processed for the request and not retained, and provides external verification of its privacy architecture. **Inference:** those privacy properties do not make PCC “local-only”; content still leaves the device. Explicit routing and user expectations remain application responsibilities. [PCC technical overview](https://developer.apple.com/videos/play/wwdc2026/319/)

PCC's model availability check is not proof that an app possesses the entitlement: Apple's current detection guide warns that an unentitled app can appear available and then fatally fail on its first prompt. Verify entitlement/provisioning before exposing that path. [PCC authentication caveat](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models)

## MLX and the wider ecosystem

Apple links the existing `ml-explore/mlx-swift-lm` package, which now includes `MLXFoundationModels`. `MLXLanguageModel` conforms to the framework's provider protocol and supports sessions, tools, streaming, and guided generation. It requires the 27 SDK and OS availability checks; with an older SDK the adapter module is empty. `FoundationModelsIntegration` is an enabled-by-default package trait. Capabilities are declared explicitly, not inferred from a model name; the default is guided generation, with tools, reasoning, and vision opt-ins. Local weight directories and custom loaders are supported. **Inference:** MLX and Foundation Models are now composable, so this is not necessarily an either/or engine decision. The chosen weights still determine usefulness. [MLX bridge documentation, pinned to Holdfast's resolved revision](https://github.com/ml-explore/mlx-swift-lm/blob/3b339ad6e3b3f44c8121ecff5131c7fd55e075e6/Libraries/MLXFoundationModels/README.md)

Separately, the same package's `MLXGuidedGeneration` constrains JSON Schema/EBNF output directly with MLX on macOS 14+/iOS 17+, without Foundation Models. **Inference:** if the immediate problem is reliable JSON shape, compare this path against Apple's model using identical cases; robust formatting alone does not justify raising Holdfast's minimum OS to 26 or 27. The library warns against cold grammar compilation on the UI thread. [Standalone constrained generation, same pinned revision](https://github.com/ml-explore/mlx-swift-lm/blob/3b339ad6e3b3f44c8121ecff5131c7fd55e075e6/Libraries/MLXGuidedGeneration/README.md)

The provider protocol separates lightweight model configuration/capabilities from an executor that translates requests and streams results. Apple links Claude and Gemini implementations, but provider authentication, billing, privacy, and supported capabilities remain provider-specific. [Provider API](https://developer.apple.com/documentation/foundationmodels/languagemodel), [provider implementation session](https://developer.apple.com/videos/play/wwdc2026/339/)

Apple's utilities package supplies a Chat Completions provider, rolling-window and summarization helpers, and just-in-time skills. The README currently illustrates `1.0.0-beta6`; treat experimental helpers as dependencies to pin and evaluate, not as a mature application policy layer. [Foundation Models utilities](https://github.com/apple/foundation-models-utilities)

The `fm` CLI comes preinstalled with macOS 27 and supports interactive chat, single responses, images, schemas, and switching to PCC. It is convenient for experiments; the video does not establish an exception to third-party app PCC eligibility. [CLI session](https://developer.apple.com/videos/play/wwdc2026/334/)

The Python SDK has a different minimum: its README requires macOS 26+, Xcode 26+, Python 3.10+, and a compatible Mac with Apple Intelligence. It provides on-device inference, streaming, and guided output, useful for batch experiments. Do not incorrectly label every new tool as requiring macOS 27. [Python SDK](https://github.com/apple/python-apple-fm-sdk)

## Images, evaluations, and failure handling

OS 27 adds image attachments to prompts. Supported inputs include native image objects, buffers, and file URLs; larger images use more tokens and time. Built-in Vision-backed OCR and barcode tools complement visual understanding, and a Spotlight search tool supports local retrieval. **Inference:** these are promising for receipt/file intake but need a separate evaluation from plain-text extraction. [What's new](https://developer.apple.com/videos/play/wwdc2026/241/)

Evaluations (27.0) provides typed datasets, sample generation, metrics, model judges, and aggregated results across models available through Foundation Models. Its purpose is measuring feature quality and regressions, not making model behavior deterministic. Tool-trajectory evaluation is also part of its API. **Suggested Holdfast measurements:** candidate-ranking accuracy, grounded source-ID precision, evidence-span validity, false links, refusal rate, latency, and any forbidden data routing. Keep deterministic privacy/edit invariants in ordinary tests. [Evaluations](https://developer.apple.com/documentation/evaluations), [tool evaluation](https://developer.apple.com/documentation/evaluations/evaluating-tool-calling-behavior)

Guardrail violations and model refusals are separate outcomes. A plain-string response may contain a refusal; guided generation throws a refusal error because the requested structure has no place for refusal prose. The documented permissive content-transformation mode only affects string generation; guided output still uses default checks, and the model can refuse even in permissive string mode. **Inference:** sensitive personal, health, or counseling notes need representative evaluation and a graceful fallback; do not assume structured extraction is exempt. [Safety and refusal documentation](https://developer.apple.com/documentation/foundationmodels/improving-the-safety-of-generative-model-output)

OS 27's `LanguageModelError` covers context overflow, rate limits, refusal, guardrails, unsupported capabilities/content/guides/locales, and timeouts; OS 26 uses `LanguageModelSession.GenerationError`. Provider capabilities should be checked before requests, and failure recovery should preserve the application's privacy policy. [Error reference](https://developer.apple.com/documentation/foundationmodels/languagemodelerror), [provider errors](https://developer.apple.com/videos/play/wwdc2026/339/)

Apple's acceptable-use requirements also apply; among other restrictions, they prohibit bypassing framework guardrails and unsupervised decisions with material impact in high-risk domains. This is distinct from whether a benign request happens to be refused by a model. [Acceptable-use requirements](https://developer.apple.com/support/terms/acceptable-use-requirements-for-the-foundation-models-framework/)

## Uncertainties to settle with a prototype

- The original research had no benchmark. The follow-up above measures a bounded cross-link comparison; it does not establish general quality, population refusal frequency, true cold latency, total Apple model memory, memory competition under other workloads, or battery impact.
- The correct context size is runtime-dependent. Some older explanatory pages still state 4K; current device/variant documentation and runtime checks take precedence.
- WWDC says context inspection/token counting arrived in 26.4, while the current `contextSize` reference metadata labels it 26.0. Confirm exact build/runtime availability with the selected SDK before choosing a deployment gate. [WWDC overview](https://developer.apple.com/videos/play/wwdc2026/241/), [contextSize](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/contextsize)
- PCC entitlement/account eligibility and numeric quotas were not verified for this developer. No account changes or entitlement application were made.
- A practical first pilot is one bounded, typed result from a small supplied candidate set, benchmarked separately on available Core/Core Advanced versions. Preserve existing provider fallback, source verification, approval, and local-only routing. This is an engineering recommendation, not an Apple capability guarantee.

## Holdfast-specific assessment

The current working tree, including pre-existing uncommitted changes, was inspected. The application remains unchanged by this research.

- `Sources/holdfast/CrossLink.swift` supplies two 1,500-character excerpts to `judge`, then parses a Boolean and reason from model text. Private notes are excluded. **Recommendation:** this is the smallest useful typed-generation pilot; retain candidate retrieval, privacy exclusions, reason scrubbing, and Inbox approval.
- `Sources/holdfast/Drop.swift` can include 12,000 document characters or 40,000 transcript characters, plus related notes and manuals. **Recommendation:** prototype short extraction before attempting unchanged full filing prompts; count tokens and reserve output space.
- `Sources/holdfast/Ask.swift` supplies retrieved passages, previous turns, and folder instructions. `Config.contextChunks` is eight. **Recommendation:** a limited system-model answer path needs a smaller budget and citation/abstention evaluation. It would not eliminate embedding or transcription downloads.
- `Runtime/pi/README.md` describes the regular Pi runner and six native tools. `Packages/ModelProviders/Sources/ModelProviders/Inference.swift` is inference-only. `Sources/holdfast/PiAgent.swift` forces protected content onto LocalMLX before inference. **Recommendation:** isolate helpers first; a native Foundation Models tool loop is a separate runner experiment with explicit privacy, persistence, cancellation, and approval behavior.
- `Package.resolved` pins MLX LM 3.32.3 at `3b339ad6e3b3f44c8121ecff5131c7fd55e075e6`; the local dependency contains both bridge and standalone grammar modules. `Package.swift` does not wire those products into Holdfast. Compare constrained output with identical MLX weights before attributing gains to changing the model.

## Follow-up: a Mac App Store route

Apple Developer Program membership costs US$99 annually, with local pricing where available. Organization enrollment requires a legal entity and D-U-N-S number. Holdfast's signed Developer ID release suggests membership may already exist, but account status was not inspected. [Enrollment](https://developer.apple.com/help/account/membership/program-enrollment)

Create a macOS app record in App Store Connect with the bundle ID and SKU; configure Store distribution signing/provisioning, upload a build, test with TestFlight, complete listing/privacy/export information, and submit for review. Existing Developer ID distribution is a different channel. [App record](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-a-new-app), [certificates](https://developer.apple.com/help/account/certificates/certificates-overview/), [workflow](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-workflow/), [TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/), [privacy details](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)

The Mac App Store requires App Sandbox. User-selected folders can be accessed through appropriate permissions and persisted with security-scoped bookmarks. [Sandbox requirement](https://developer.apple.com/documentation/security/app-sandbox), [file access](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)

Focused code observations and implications:

| Observation | Store preparation |
| --- | --- |
| `scripts/sign_app.py` gives the main app an audio entitlement, Node a JIT entitlement, and only the Quick Look extension the sandbox entitlement. No security-scoped bookmark handling was found in app sources. | Add and test the main app's required access restrictions, persistent vault/model-folder permission, and helper behavior. |

The relevant review rules require a self-contained bundle, constrain downloading code/resources that change functionality, and prescribe Store updates. Model asset downloads and custom imports need specific review against those requirements. Apple's documentation separately describes embedded command-line helpers; a subprocess architecture is not by itself proof that the runtime must be removed. This was not a full review or a submitted build. [Review guidelines, 2.4.5 and 2.5.2](https://developer.apple.com/app-store/review/guidelines/), [embedded helpers](https://developer.apple.com/documentation/xcode/embedding-a-helper-tool-in-a-sandboxed-app), [distribution preparation](https://developer.apple.com/documentation/xcode/preparing-your-app-for-distribution)

For PCC, Small Business Program enrollment and the managed entitlement are additional steps; App Store approval alone is insufficient. **Recommendation:** pursue Store distribution for product/discovery value, then add PCC as an optional remote capability if eligible. Keep direct distribution and on-device inference available according to the product's chosen channel strategy. [Small Business Program](https://developer.apple.com/app-store/small-business-program/), [PCC eligibility](https://developer.apple.com/private-cloud-compute/)
